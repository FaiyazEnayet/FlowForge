# Changelog

## Unreleased
### Added
- Causal history conditioning (`flowforge/data.py`, `flowforge/models.py`, `examples/history_ablate.py`): the models can now condition on the full 60 seconds of book features before each window, not only on the two-number regime summary of that past. `build_dataset` gains an opt-in `with_past_context` flag: every window then carries a past-context tensor holding the LOOKBACK seconds immediately before its start, drawn strictly from earlier seconds inside the same recording segment (windows exist only where the full lookback is in-segment, so a context never crosses a recording gap or a session boundary), plus a boolean availability mask, standardized with the same train-split feature statistics as the windows themselves and carried through save/load with dtype, shape, and finiteness validation; datasets without context load exactly as before, and building with context leaves the split manifest and its SHA untouched. A new `CausalContextEncoder` (left-padded dilated convolutions at dilations 1, 2, 4, 8 with per-position normalization, so a context position never sees later positions and no sequence-wide statistic leaks into early positions) embeds the context; masked-out seconds are zeroed before the convolutions and excluded from the pooling, so unavailable seconds cannot influence the embedding, and a window with no available context embeds as zero. `BookDDPM` gains `use_history`: the denoiser's conditioning vector becomes timestep, regime, and context embedding concatenated, and training and sampling thread the context through with loud errors on misuse (a history model requires its context; a plain model rejects one handed to it). `CondVAE` gains the matching `context_dim`, conditioning its decoder the same way. Everything is opt-in and off by default: with history off, model construction, parameter counts, training, and fixed-seed sampling are unchanged, and the two-number regime variant stays as the comparator. The preregistered ablation in `examples/history_ablate.py` (arms: regime-only DDPM, history-conditioned DDPM on the true past, the same architecture with the context withheld, chunk-copy; primary metrics: conditional W1 and conditional MMD by train-tercile regime bin; guardrails: marginal W1, flow ACF error, held-out discriminator AUC, tolerance 0.05; nearest-neighbour coverage ratio reported without a verdict role) ran on a synthetic fixture whose windows genuinely depend on their past beyond the two summary numbers (window volatility follows the context's late volatility rather than its whole-minute average, and signed flow and returns continue across the context/window boundary as one AR sequence; 240 train / 120 val / 120 test pairs, seeds 7 and 107, 30 epochs; the recorded dataset NPZ is not committed, so these numbers describe the protocol on the fixture, not the recorded market data, and are not comparable to the published real-data results): the result is a null on the primary metrics. Conditional W1 was 1.308 for the history arm against 1.286 for the regime-only arm and conditional MMD 0.376 against 0.370, and the context-withheld arm landed at 1.315 and 0.376, so at this fixture scale and training length the context content itself added nothing measurable beyond the extra capacity (76,631 parameters against 55,447); the guardrails stayed within tolerance (marginal W1 1.293 against 1.273, flow ACF error 0.064 against 0.075, discriminator AUC 0.997 against 1.000, saturated on this fixture as in the P02 and P06 runs), and the nearest-neighbour ratio was 2.89 against 2.86, so the history arm is not copying its way to its scores either. History conditioning ships as a tested experimental option alongside the regime conditioning, which remains the default; the fixture's chunk-copy baseline again scored best on fidelity, recorded as a fixture artifact rather than a model ranking, as in C04 and P02.
- Factorized feasible top-of-book representation (`flowforge/factorized.py`, `examples/factorized_ablate.py`): an experimental six-channel representation (log return, log spread, log total depth, imbalance, signed flow, log trade count) in which the bid/ask size pair is derived exactly from total depth and imbalance (bid = depth * (1 + imbalance) / 2, ask = depth * (1 - imbalance) / 2) instead of being generated as two independent channels, complementing the C04 structural variant, which drops the imbalance channel and keeps both sizes. The encode/decode pair is exactly invertible on physically valid windows; the two re-expressed channels (log spread, modeled directly so the decoded spread is positive by construction, and log total depth) take their normalizers from the windows handed to the encoder, which the caller restricts to the training split. `FactorizedBookDDPM` adds an optional hurdle gate head for the trade count: with the hurdle decode, seconds the gate calls tradeless get count exactly 0 and signed flow exactly 0, and traded seconds get a positive integer count. A raw audit (`audit_factorized_windows`) reports generated factorized windows before any decode bound is applied (out-of-range imbalance, channels beyond the documented decode safety bounds, negative raw counts, raw zero-count seconds with nonzero flow), so nothing is bounded silently. The preregistered ablation in `examples/factorized_ablate.py` (arms: raw DDPM, factorized DDPM, post-hoc projection of the raw arm's own samples, factorized DDPM with the discrete head, VAE, chunk-copy; validity composite = mean of imbalance violation, negative spread, non-integer count, and coherence rates; guardrails: marginal W1, flow ACF error, held-out discriminator AUC, tolerance 0.05; exact parameter counts reported per arm) ran on the same synthetic fixture as the P06 ablation (240 train / 120 val / 120 test windows, seeds 7 and 107, 30 epochs; the recorded dataset NPZ is not committed, so these numbers describe the protocol on the fixture, not the recorded market data, and are not comparable to the published real-data results): the validity result is exact and the fidelity result is a null. The hurdle arm audited at zero on every validity check in both seeds (composite 0.000 against the raw arm's 0.571: imbalance violation 0.983, negative spread 0.119, non-integer count 0.981, coherence 0.204), and the representation-only arm reached 0.074 with only coherence violations remaining (0.295, the constraint the discrete head exists to close); the raw audit counted the decode bounds doing their work (7.8 percent of the hurdle arm's raw cells carried out-of-range imbalance, 2.9 percent for the representation-only arm, with zero out-of-bound depth or spread channels and zero non-finite cells). But the hurdle arm's marginal W1 was 2.258 against the raw arm's 1.405 and its flow ACF error 0.134 against 0.072, outside the preregistered 0.05 guardrail tolerance (discriminator AUC was 1.000 in both arms, saturated on this fixture at this training length, as in the P06 and C04 fixture runs), so the improvement criterion is formally unmet and no improvement is claimed. The representation-only arm's fidelity was mixed (marginal W1 1.329, better than raw; flow ACF error 0.109 and cross-correlation error 0.138, worse). Parameter counts were near-equal by construction (55,207 factorized against 55,447 raw), and sampling latency was comparable (0.032 against 0.027 seconds per window). The factorized representation ships as a tested experimental variant alongside the structural one; the shipped seven-feature representation and its training path are unchanged, and the fixture's chunk-copy baseline again scored best on fidelity, recorded as a fixture artifact rather than a model ranking, as in C04.
- Statistical-structure auxiliary losses for the DDPM (`flowforge/losses.py`, `flowforge/models.py`, `examples/aux_loss_ablate.py`): three optional penalties compare the differentiable denoised estimate of a clean window against that same training window: within-window lag autocovariance of log returns and signed flow at lags 1-5, the distribution of per-window realized volatility (matched by rank pairing), and return/flow dependence (contemporaneous correlation plus both lag-1 cross-correlations). `BookDDPM.p_loss` and `train_ddpm` accept `aux_weights`; the default is None, so existing training is unchanged, and the predeclared low weights are 0.01 per component. The penalties are training-only by construction: each takes only the estimate and the training batch itself (detached), so no validation or test statistic can enter the training loss, and the structural variant rejects them explicitly. A spectral-domain penalty is NOT included: at the training batch size of 32 windows, split-half mean periodograms of the same spectrum disagree by about 29 percent per bin on average (30 non-DC bins on a 60-step window), so a frequency target would mostly chase sampling noise; the decision and its measurement (`assess_spectral_stability`) are recorded in `flowforge/losses.py`. The preregistered ablation in `examples/aux_loss_ablate.py` (primary metrics: flow and return ACF error, realized-volatility W1, return/flow correlation error; guardrails: marginal W1, held-out discriminator AUC, imbalance violation rate, tolerance 0.05) ran on a synthetic fixture with known temporal structure (240 train / 120 val / 120 test windows, seeds 7 and 107, 30 epochs; the dataset NPZ is not committed, so these numbers describe the protocol on the fixture, not the recorded market data, and are not comparable to the published real-data results): the result is a null. The auxiliary arm's primary composite was 0.536 against the plain arm's 0.525 (flow ACF error 0.073 vs 0.072, return ACF error 0.032 vs 0.030, realized-volatility W1 1.94 vs 1.91, cross-correlation error 0.094 vs 0.090), so no improvement is claimed; guardrails stayed within tolerance (marginal W1 1.430 vs 1.405, imbalance violation 0.984 vs 0.983, discriminator AUC 1.000 in both arms, saturated on this deliberately simple fixture at this training length, as in the C04 fixture runs). The penalties ship as an available, tested option that is off by default; the weights were not tuned against the fixture's test split.
- Physical audit and constrained generative representation (`flowforge/evaluate.py`, `flowforge/models.py`): the book-consistency audit now measures the RAW imbalance residual before any clipping (the previous audit clipped the generated imbalance to [-1, 1] first, hiding out-of-range violations) and records the raw imbalance range and out-of-range rate, sign/finite/overflow checks, spread nonnegativity, trade-count nonnegativity and integer validity, and count/flow coherence (a zero-trade second must have zero signed flow); the audit only reports and never mutates its input, and `derive_imbalance` is overflow-safe so extreme log sizes yield a finite in-range value instead of nan. `BookDDPM.sample` gains explicit `mode="raw"` (default, draw stream unchanged) and `mode="constrained"` (imbalance derived solely from the generated log sizes, same stream, so a constrained sample is exactly the constrained transform of the raw sample for a fixed seed). `full_report` now evaluates BOTH modes under the identical held-out protocol and reports a `postprocessing_quality_loss` block (constrained minus raw for mean W1, discriminator AUC, and TSTR accuracy) as measured, including when adverse or null. An experimental `StructuralBookDDPM` trains over the six structural features (FEATURE_NAMES minus imbalance) with a hurdle gate head for the trade count and reconstructs full windows deterministically at decode: imbalance derived from the decoded sizes, spread and sizes through invertible positive transforms, counts as nonnegative integers with signed flow zeroed wherever the count is zero, so decoded windows satisfy the audit by construction; the variant's docstring states plainly that top-of-book aggregates do not encode the message stream and no message-level execution reconstruction is claimed. Evaluation parity was exercised end to end on a synthetic coherent fixture (240/60/60 train/val/test windows, single session; the dataset NPZ is not committed, so these numbers describe the protocol on the fixture, not the recorded market data): under the C03 protocol (seeds 7/107/207, block lengths 1/5/10/20, identical discriminator) the raw DDPM's imbalance violated at rate 0.996 with raw range [-7.56, 7.29], the constrained mode's paired W1 was lower by 0.543 (block-20 CI [0.522, 0.576]), the seed-7 quality loss was mixed (mean W1 -0.540, discriminator AUC +0.015 adverse, TSTR 0.000 null), the structural model's decoded windows audited at zero violations on every check (one cell of 3600 sat at |imbalance| = 1 + 1.1e-8, float32 storage dust), and the simple baselines beat the small briefly-trained neural models on this deliberately simple fixture, which is recorded as a fixture artifact rather than a model ranking.
- Baseline parity and dependence-aware comparison intervals (`flowforge/baselines.py`, `flowforge/evaluate.py`, `examples/demo.py`): moving-block resampling is now session/segment-safe (blocks are drawn only from starts whose whole block lies inside one recording segment, never wrapping across a boundary) and reports the training indices behind every generated window; the VAR baseline fits its lag sequences only inside one valid session or segment and starts generation from in-segment runs. Two conditional comparators join the unconditional pair: a regime-matched chunk-copy baseline (copies the training block whose starting regime is closest to the target regime) and a lightweight conditional autoregressive baseline (per-timestep ridge VAR inside each window with the regime as an input, fit on within-window transitions only). The demo now runs a baseline parity comparison (`flowforge-baseline-parity/1` schema in `runs/metrics.json`): DDPM, VAE, chunk-copy, conditional AR, and VAR are scored under identical test conditions with the same held-out discriminator protocol, the same seed set (7, 107, 207), and complete latency, memory, and NFE accounting on every run. W1 differences get paired block-bootstrap intervals from identical chronological resampled blocks, discriminator AUC gets blocked intervals over the real and generated score groups, and TSTR differences are paired over blocks of the shared test windows, at block lengths 1, 5, 10, and 20. With one test session, the report labels its intervals within-session rather than across-day evidence.
- Architecture ablation contract, baseline capture, and independent receptive-field oracle (`examples/architecture_ablate.py`): the architectures under comparison for the Denoiser (current CNN; dilated residual TCN with the explicit dilation cycle 1, 2, 4, 8, 16, 32; compact downsample/upsample 1-D U-Net; optional attention) are declared as layer specs, with a parameter budget rule (within 5 percent of the baseline count, channel width is the knob), a paired wall-time comparator protocol (latency is only compared within one run, same shape, median of timed passes after warmup), and a measurement protocol (theoretical receptive field, empirical gradient influence, conditioning gradient sensitivity at distant offsets). The oracle computes receptive fields and influence spans from the specs with plain integer arithmetic and shares no code with the models; its answers are pinned against hand-computed known answers in tests. Baseline capture under run ID `p04-part1-baseline` (capture SHA-256 `0d22f3ac5d187978...`, initialised-weights SHA-256 `5613a28f56b682ca...`): the current Denoiser has 221,767 parameters and a theoretical receptive field of 17 positions (half width 8) against the 60-position window, so it has no full-window context; the measured gradient influence of an input on a late prediction matches the oracle span (in-span maximum gradient 0.27 to 0.50 across the probed targets) with only a weak out-of-span remainder (maximum-gradient ratio 0.025 to 0.046, against a pinned bound of 0.15) that comes from GroupNorm statistics spanning the window, and is recorded as such rather than treated as feature-path context. Conditioning reaches distant offsets by construction (regime gradient sensitivity 0.164 at the last offset). The oracle validates the part 2 candidate claims before anything is built: the TCN spec reaches receptive field 257 (full-window), the U-Net spec 37 (wider than baseline, not full-window), and the attention spec is global. Forward latency under the paired protocol: 8.43 ms median at batch 32 on the capture machine, recorded for within-run comparison only. Part 1 promotes nothing; the candidate implementations and the paired fidelity, separation, latency, and overfit comparison are part 2.
- Candidate denoiser architectures and the paired architecture comparison (`flowforge/models.py`, `examples/architecture_ablate.py`): `BookDDPM` gains an `arch` selector over `DENOISER_ARCHITECTURES`; the default `cnn` path constructs the shipped Denoiser exactly as before, so the part 1 capture stays reproducible. The three candidates implement the part 1 specs at budget-matched widths (baseline 221,767 parameters, ceiling 232,855): a dilated residual TCN (`ResBlock` gains a dilation parameter, default 1; six blocks at dilations 1, 2, 4, 8, 16, 32; 214,855 parameters, -3.1 percent), a compact downsample/upsample 1-D U-Net (two stride-2 stages, additive skip connections, upsampling targeted at the skip length so odd window lengths keep their exact shape; 224,359 parameters, +1.2 percent), and an attention variant (one unmasked multi-head self-attention block with a position-wise feed-forward network; 220,379 parameters, -0.6 percent). `compare_architectures` runs the paired comparison in a single run (identical data, seed streams, and step counts; the baseline re-measured in the same run): fidelity is the marginal W1 of samples generated for the validation regimes, separation is the discriminator fit on validation and scored on test, latency follows the part 1 paired protocol, and overfit curves are per-epoch train and validation p-loss under one fixed evaluation stream. Measured on the historical dataset (996/168/168 windows, archive SHA-256 `1d70476e9f2c...`, 12 epochs, run ID `p04-part2-comparison`): fidelity W1 was 0.2397 (U-Net), 0.2476 (attention), 0.2512 (CNN), 0.2799 (TCN); test discriminator AUC was 0.703 (attention), 0.746 (TCN), 0.806 (CNN), 0.889 (U-Net), while the validation AUC saturated at 1.000 for every architecture because there the discriminator is scored on its own fit split; forward latency at batch 32 was 3.00 ms (U-Net), 3.65 ms (CNN), 7.11 ms (TCN), 13.14 ms (attention); final validation p-loss was lowest for the CNN (0.1952, then attention 0.2017, U-Net 0.2237, TCN 0.2279) and no validation curve had turned up by epoch 12. The metrics disagree, so no candidate is promoted and the shipped CNN remains the default: wider receptive fields did not buy a consistent fidelity or separation win at this budget and training length. Empirical influence at init is pinned per claim in tests: the TCN gradient at offsets 19, 29, and 41 for the last target is 3.4 to 5.9 times the baseline gradient at the same offsets, while its extreme-corner gradient (offset 0, distance 59) stays at the normalization-leakage level at init despite the connecting path; the U-Net influence matches its own span (half width 18, out-of-span maximum-gradient ratio 0.089 to 0.094 against the 0.15 bound) and it is not credited with global context; the attention block's output at the last position moves when only input offset 0 is perturbed while the block's input there is exactly unchanged, demonstrating that the global mix is exercised. Post-training influence in the comparison run shows the TCN distant-offset gradient growing to 0.048 at offset 29 (baseline 0.006), while the attention model's distant gradients stay at the 0.005 to 0.007 level after 12 epochs.
- Causal multiwindow rollout contract (`flowforge/rollout.py`): Part 1 advances context from an anchor history and previously generated rows only. Main baseline at `de3237e`: 198 passed, 1 skipped. The synthetic fixture is not comparable to published real-data metrics; no performance claim is made.
- Regime stratification and regime-balanced training (`flowforge/strata.py`, `flowforge/data.py`, `flowforge/models.py`, `flowforge/evaluate.py`, `examples/strata_ablate.py`): windows are now stratified by causal past features computed strictly from the 60 seconds before each window (past volatility, spread, trade activity, depth), with thresholds fitted on TRAIN only and applied unchanged to val/test, and with outcome labels derived from the window's own return kept as a separate analysis-only type that every training entry point refuses. `build_dataset` records per-window past trade activity and depth alongside the existing past volatility and spread, carried through save/load with dtype, shape, and finiteness validation; datasets built before this change load the new fields as None and `past_features` refuses them loudly instead of inventing values. `train_ddpm` and `train_vae` accept optional per-window importance weights and regime stratum labels: weights reweight the per-example loss, labels build round-robin stratified minibatches at exactly the same optimizer step count per epoch as uniform sampling (equal compute), and both are off by default so existing training is unchanged; a capped-weight effective-sample-size diagnostic is reported. `full_report` gains an opt-in per-stratum section (mean W1, nearest-neighbour coverage, diversity ratio per stratum, plus average and worst-stratum summaries), and any stratum holding fewer than 10 independent non-overlapping episodes raises NotEnoughDataError instead of publishing a number. The gate that blocked this unit on 2026-11-10 (one 4-hour night, extreme strata at single-digit independent episodes) now passes on the expanded 28-session corpus (8 original chunks plus the 20 B1-QC 4-hour BTCUSDT sessions recorded Nov 9-12, 2026; 302,340 s, 83.98 h; windows train 18,468 / val 5,712 / test 5,712; manifest SHA b7c40026cca52f826a4f0cb5f7025faab907627a8c9cbd74fb861e1446ae581e): minimum independent episodes per past-volatility decile are train 139, val 10, test 28. The preregistered ablation in `examples/strata_ablate.py` (arms: uniform, capped importance weights over the binary tail partition of top past-volatility decile vs rest with cap 10 and effective sample size 6,649 of 18,468, stratified minibatches across the ten deciles, regime-matched chunk-copy reference; 12 epochs, batch 32, seed 0; evaluation on a fixed 2,000-window stratified subsample of test with a matching val subsample, seed 1234; verdict rule: an arm improves only if worst-stratum mean W1 is strictly lower than uniform and average coverage is no lower and no guardrail degrades by more than 0.05; the dataset NPZ is not committed, so these numbers describe the protocol on the dataset whose manifest SHA is recorded above, not a committed artifact): the result is a null on the preregistered verdict. Capped weights cut the worst-stratum mean W1 to 0.269 against uniform 0.353 and the mean W1 to 0.111 against 0.169, with tail W1 0.00117 against 0.00123 and tail rate ratio 0.66 against 0.49, but average coverage fell to 0.491 against 0.517, so the improvement criterion is unmet and no improvement is claimed; stratified minibatches reached worst-stratum mean W1 0.340 with average coverage 0.425, also null. Guardrails stayed within tolerance for both arms (flow ACF error 0.010 and 0.020 against uniform 0.008; discriminator AUC distance from 0.5 was 0.323 and 0.359 against 0.325). The chunk-copy reference again scored best on fidelity (worst-stratum mean W1 0.133, mean W1 0.062), recorded as a reference artifact rather than a model ranking. Limitations: single seed, 2,000-window subsample, stratification on the past-volatility decile only, and test sessions (Nov 11-12) more volatile than train (18.6 percent of test windows sit above the train top-decile volatility threshold).
- Diffusion schedule, prediction objective, EMA, and training-regularity options (`flowforge/models.py`, `examples/diffusion_ablate.py`, `examples/demo.py`): `BookDDPM` gains a `schedule` selector (linear, sqrt, quadratic, sigmoid; the cosine schedule is refused, having diverged when tried before) with an independent `beta_end`, and an `objective` selector (epsilon, v, x0) with exact prediction conversions between them, all recorded on the model and in checkpoints; the linear schedule reproduces the shipped betas bit-for-bit and a terminal-noise gate asserts alpha_bar_T below 0.05 for every schedule, so no schedule can silently end under-diffused. `train_ddpm` gains a cosine learning-rate schedule, gradient clipping, and EMA warmup (the effective decay ramps from the warmup rule to the configured decay over the first warmup steps and is exactly the configured decay with warmup off), and the demo records the schedule and objective in each checkpoint config. Everything is opt-in and off by default: with defaults, model construction, parameter counts (221,767), training, and fixed-seed sampling are unchanged. The preregistered ablation in `examples/diffusion_ablate.py` (10 arms at identical data, architecture, epochs, batch, seeds, and step counts on the expanded 28-session corpus, 8 original chunks plus the 20 B1-QC 4-hour BTCUSDT sessions recorded Nov 9-12, 2026; train 18,468 / val 5,712 / test 5,712 windows; manifest SHA b7c40026cca52f826a4f0cb5f7025faab907627a8c9cbd74fb861e1446ae581e; 6 epochs, batch 32, seed 0; evaluation on a fixed 1,000-window strided subsample of val, seed 7; verdict rule: an arm improves only if val mean W1 is at least 0.02 below baseline and val p-loss is no more than 0.01 above baseline; the dataset NPZ is not committed, so these numbers describe the protocol on the dataset whose manifest SHA is recorded above, not a committed artifact): the result is a null on the preregistered verdict, and no option is promoted. The baseline scored val mean W1 0.1070 with val p-loss 0.1929; the closest arm, quadratic schedule, reached W1 0.1060 with p-loss 0.2717, and gradient clipping reached W1 0.1071 with p-loss 0.1927, both short of the improvement bar, while the sqrt and sigmoid schedules (W1 0.1661 and 0.1571), the v and x0 objectives (W1 0.1229 and 0.3316), EMA with and without warmup (W1 0.1074 and 0.1138), and cosine learning rate (W1 0.1141) all scored worse than baseline on fidelity; sampling throughput was comparable across arms (33 to 46 seconds per 1,000 windows at 100 function evaluations per window). No factorial combination was run, since no single option improved. The options ship as tested experimental settings alongside the unchanged defaults. Limitations: single seed, 1,000-window validation subsample, and the test split was scored by no arm and never used for tuning.

## [v1.1.0] - 2026-10-16

### Fixed
- Autocorrelation evaluation (`flowforge/evaluate.py`). `flow_acf_table` concatenated signed order flow across overlapping windows (60s windows, 10s stride) before computing autocorrelation. That duplicated most of the data, scrambled temporal order at window junctions, and centered everything on the grand mean. On level-shifted synthetic data the old method reported lag-1 autocorrelation of 0.97 where the true value was 0.3. It now computes autocorrelation per window and averages across windows, with 95% confidence intervals. Added regression tests pinning the per-window behavior and CI coverage.

### Added
- Train-on-synthetic-test-on-real (TSTR) check (`flowforge/evaluate.py`). A logistic regression predicts near-term flow direction from generated windows and is tested on real test windows, next to the same model trained on real windows, with a majority-class baseline for scale. It is reported separately from the real-vs-generated discriminator, which asks whether synthetic windows are indistinguishable rather than whether they are useful. First run: diffusion-trained scores 0.626 (the majority baseline), VAE-trained scores 0.409, so the VAE's invented temporal structure is actively misleading.

### Changed
- Reran the VAE baseline and the DDPM (seed 7, same config) and updated the README with the new numbers: DDPM mean W1 0.280 (was 0.277), discriminator AUC 0.741 (was 0.669). The AUC moved between identical reruns because torch CPU training is not bit-reproducible across runs; I verified the discriminator itself is deterministic on fixed inputs, so the movement is training noise. The W1 moved only in the third decimal.

### Fixed
- Conditioning leakage in the regime features (`flowforge/data.py`). The volatility lookback was built as `mid[start - LOOKBACK:start + 1]`, which included `mid[start]`, the first second of the target window the model generates, contradicting the documented strictly-past conditioning. It now uses `mid[start - LOOKBACK:start]`. Added a regression test pinning temporal invariance: regime features for a window are identical when data at or after the window start is perturbed.

### Changed
