# Changelog

## Unreleased
### Added
- Baseline parity and dependence-aware comparison intervals (`flowforge/baselines.py`, `flowforge/evaluate.py`, `examples/demo.py`): moving-block resampling is now session/segment-safe (blocks are drawn only from starts whose whole block lies inside one recording segment, never wrapping across a boundary) and reports the training indices behind every generated window; the VAR baseline fits its lag sequences only inside one valid session or segment and starts generation from in-segment runs. Two conditional comparators join the unconditional pair: a regime-matched chunk-copy baseline (copies the training block whose starting regime is closest to the target regime) and a lightweight conditional autoregressive baseline (per-timestep ridge VAR inside each window with the regime as an input, fit on within-window transitions only). The demo now runs a baseline parity comparison (`flowforge-baseline-parity/1` schema in `runs/metrics.json`): DDPM, VAE, chunk-copy, conditional AR, and VAR are scored under identical test conditions with the same held-out discriminator protocol, the same seed set (7, 107, 207), and complete latency, memory, and NFE accounting on every run. W1 differences get paired block-bootstrap intervals from identical chronological resampled blocks, discriminator AUC gets blocked intervals over the real and generated score groups, and TSTR differences are paired over blocks of the shared test windows, at block lengths 1, 5, 10, and 20. With one test session, the report labels its intervals within-session rather than across-day evidence.
- Architecture ablation contract, baseline capture, and independent receptive-field oracle (`examples/architecture_ablate.py`): the architectures under comparison for the Denoiser (current CNN; dilated residual TCN with the explicit dilation cycle 1, 2, 4, 8, 16, 32; compact downsample/upsample 1-D U-Net; optional attention) are declared as layer specs, with a parameter budget rule (within 5 percent of the baseline count, channel width is the knob), a paired wall-time comparator protocol (latency is only compared within one run, same shape, median of timed passes after warmup), and a measurement protocol (theoretical receptive field, empirical gradient influence, conditioning gradient sensitivity at distant offsets). The oracle computes receptive fields and influence spans from the specs with plain integer arithmetic and shares no code with the models; its answers are pinned against hand-computed known answers in tests. Baseline capture under run ID `p04-part1-baseline` (capture SHA-256 `0d22f3ac5d187978...`, initialised-weights SHA-256 `5613a28f56b682ca...`): the current Denoiser has 221,767 parameters and a theoretical receptive field of 17 positions (half width 8) against the 60-position window, so it has no full-window context; the measured gradient influence of an input on a late prediction matches the oracle span (in-span maximum gradient 0.27 to 0.50 across the probed targets) with only a weak out-of-span remainder (maximum-gradient ratio 0.025 to 0.046, against a pinned bound of 0.15) that comes from GroupNorm statistics spanning the window, and is recorded as such rather than treated as feature-path context. Conditioning reaches distant offsets by construction (regime gradient sensitivity 0.164 at the last offset). The oracle validates the part 2 candidate claims before anything is built: the TCN spec reaches receptive field 257 (full-window), the U-Net spec 37 (wider than baseline, not full-window), and the attention spec is global. Forward latency under the paired protocol: 8.43 ms median at batch 32 on the capture machine, recorded for within-run comparison only. Part 1 promotes nothing; the candidate implementations and the paired fidelity, separation, latency, and overfit comparison are part 2.
- Candidate denoiser architectures and the paired architecture comparison (`flowforge/models.py`, `examples/architecture_ablate.py`): `BookDDPM` gains an `arch` selector over `DENOISER_ARCHITECTURES`; the default `cnn` path constructs the shipped Denoiser exactly as before, so the part 1 capture stays reproducible. The three candidates implement the part 1 specs at budget-matched widths (baseline 221,767 parameters, ceiling 232,855): a dilated residual TCN (`ResBlock` gains a dilation parameter, default 1; six blocks at dilations 1, 2, 4, 8, 16, 32; 214,855 parameters, -3.1 percent), a compact downsample/upsample 1-D U-Net (two stride-2 stages, additive skip connections, upsampling targeted at the skip length so odd window lengths keep their exact shape; 224,359 parameters, +1.2 percent), and an attention variant (one unmasked multi-head self-attention block with a position-wise feed-forward network; 220,379 parameters, -0.6 percent). `compare_architectures` runs the paired comparison in a single run (identical data, seed streams, and step counts; the baseline re-measured in the same run): fidelity is the marginal W1 of samples generated for the validation regimes, separation is the discriminator fit on validation and scored on test, latency follows the part 1 paired protocol, and overfit curves are per-epoch train and validation p-loss under one fixed evaluation stream. Measured on the historical dataset (996/168/168 windows, archive SHA-256 `1d70476e9f2c...`, 12 epochs, run ID `p04-part2-comparison`): fidelity W1 was 0.2397 (U-Net), 0.2476 (attention), 0.2512 (CNN), 0.2799 (TCN); test discriminator AUC was 0.703 (attention), 0.746 (TCN), 0.806 (CNN), 0.889 (U-Net), while the validation AUC saturated at 1.000 for every architecture because there the discriminator is scored on its own fit split; forward latency at batch 32 was 3.00 ms (U-Net), 3.65 ms (CNN), 7.11 ms (TCN), 13.14 ms (attention); final validation p-loss was lowest for the CNN (0.1952, then attention 0.2017, U-Net 0.2237, TCN 0.2279) and no validation curve had turned up by epoch 12. The metrics disagree, so no candidate is promoted and the shipped CNN remains the default: wider receptive fields did not buy a consistent fidelity or separation win at this budget and training length. Empirical influence at init is pinned per claim in tests: the TCN gradient at offsets 19, 29, and 41 for the last target is 3.4 to 5.9 times the baseline gradient at the same offsets, while its extreme-corner gradient (offset 0, distance 59) stays at the normalization-leakage level at init despite the connecting path; the U-Net influence matches its own span (half width 18, out-of-span maximum-gradient ratio 0.089 to 0.094 against the 0.15 bound) and it is not credited with global context; the attention block's output at the last position moves when only input offset 0 is perturbed while the block's input there is exactly unchanged, demonstrating that the global mix is exercised. Post-training influence in the comparison run shows the TCN distant-offset gradient growing to 0.048 at offset 29 (baseline 0.006), while the attention model's distant gradients stay at the 0.005 to 0.007 level after 12 epochs.

## [v1.4.0] - 2026-10-30
### Added
- Safe NPZ dataset loading and explicit legacy migration (`flowforge/data.py`, `flowforge/demo.py`): `save_dataset` now stores chunk metadata (`chunk_dirs`, `chunk_hashes`, `chunk_symbols`) as typed UTF-8 JSON instead of NumPy object arrays, so a saved dataset contains nothing that needs pickle to read back. The default `load_dataset` opens archives with `allow_pickle=False` and validates dtypes, finiteness, and split identity against the dataset's own embedded manifest (window counts, per-split session membership, `session_split` agreement between the top-level key and the manifest); a poisoned object array, a tampered manifest, a dtype or window-count mismatch, a relabeled session id, or a non-finite tensor all fail closed. Pre-FF-N03 archives (object-array metadata) and pre-C02 archives (no manifest) load only under explicit `legacy=True` through a trusted reader, and the new `convert_legacy_dataset` migrates a trusted legacy archive to the typed format at a NEW path, never rewriting the source: a manifest-less source gains a manifest built from its own recorded metadata (its split assignment unchanged, no provenance fabricated), and the converter returns the artifact as reloaded through the default loader, so success proves the roundtrip. The historical dataset (train 996 / val 168 / test 168 windows, sessions train [0-5], val [6], test [7]) roundtrips bit-identically through converter -> new format -> default loader, and the original NPZ is preserved untouched (SHA-256 identical before and after the acceptance run). `load_demo_bundle` also loads with `allow_pickle=False`; the committed demo bundle contains no object arrays, so its behavior is unchanged.
- Device-safe time embedding and guarded, batched sampling (`flowforge/models.py`, `examples/demo.py`): `TimeEmbed` now registers its frequencies as a non-persistent buffer, so they follow module device and dtype moves instead of being rebuilt on CPU in `forward` (which failed with a device mismatch for any non-CPU placement), and state dict keys are unchanged, so existing checkpoints load exactly as before. `BookDDPM.sample` validates its inputs (a non-tensor, mis-shaped, empty, or non-finite regime raises `ValueError`, as does a non-positive `batch_size`), runs the reverse chain under `torch.inference_mode`, accepts an optional `batch_size` that chunks the regime rows (draws come from the same isolated generator in row order and a batched call is reproducible for a fixed seed and batch size; chunking changes the draw blocking, so batched values differ from the unbatched stream, whose fixed-seed CPU outputs are unchanged), and checks the chain state after every reverse step, raising `FloatingPointError` naming the step instead of silently returning non-finite windows. `sample_with_ema` passes `batch_size` through. The demo generates under inference mode with an explicit sampling batch size and audits its saved inference checkpoints by reloading them (manifest and weights digest verification) before reporting. Profiling on the recorded environment showed the per-step denoiser forward dominates sampling time, not allocation or RNG draws, so no allocation changes were made; `requirements-lock.txt` pins the profiled stack and records the hardware and backend.
- Isolated RNG streams for model init, training, and inference (`flowforge/models.py`): `CondVAE` and `BookDDPM` accept a `seed` or `run_id` for initialization, `train_vae`/`train_ddpm` accept a `run_id` alongside their seed, and `CondVAE.generate`/`BookDDPM.sample`/`sample_with_ema` accept a `generator`, `seed`, or `run_id`. Seeds derived from a run ID use SHA-256 over "run_id:stream" (init, training, and sampling streams are named separately), never Python's salted hash, so the same run ID reproduces in every process. Seeded init, training, and sampling leave the caller's torch, Python, and NumPy RNG state exactly unchanged, so building models in any order yields exactly equal initialized tensors and a fixed sampling stream reproduces to 1e-7 on CPU. Unseeded calls keep the previous global-RNG behavior, so existing demo, sweep, and checkpoint flows are unchanged.
- Exact DDPM/VAE inference checkpoints and faithful reload (`flowforge/checkpoints.py`, `examples/demo.py`): inference checkpoints hold ready-to-sample weights (the EMA shadow for a DDPM trained with EMA, otherwise the trained weights) plus a manifest with format version, model class and config, train-only normalizer, commit SHA, split-manifest SHA, and SHA-256 digests over the manifest and the weights; resumable checkpoints add the raw training weights, EMA shadow, optimizer state, and torch/Python/NumPy RNG states. Loads are fail-closed: a wrong format version, an altered manifest or weights file, or an architecture mismatch raises and loads nothing. A fresh-process reload through `python -m flowforge.checkpoints generate` reproduces the in-process samples (CPU same-backend atol<=1e-7, normalized and inverse-transformed). Historical weight tensors were never saved and are labeled unavailable, never reconstructed. `examples/demo.py` now saves inference checkpoints for both trained models under `runs/checkpoints/` and records their paths and manifest SHAs in `runs/metrics.json`.
- Canonical dataset hashes and locked split manifests (`flowforge/data.py`, `examples/build_data.py`, `examples/demo.py`, `examples/sweep.py`, `examples/build_demo.py`): chunk hashes are now full SHA-256 of explicitly ordered raw file bytes (quotes.parquet bytes, then trades.parquet bytes) instead of truncated parsed-frame bytes. The split manifest (schema v2) records per-chunk raw file hashes, raw timestamp minima/maxima, symbol, recorder metadata and schema version, session ID, UTC day, split, usable-bar count, segment count, data transform version, random seed (null: the build is deterministic), and code SHA, plus a canonical manifest SHA that excludes only the hash itself and the wall-clock creation time, so identical raw bytes in separate processes yield identical hashes. Duplicate or overlapping raw sessions are detected before any chunk is dropped, so a session whose bars are later dropped cannot hide a duplicate. The manifest SHA is saved inside the NPZ and recorded in `runs/metrics.json`, `runs/sweep.json`, and the demo bundle provenance; demo and sweep validate the manifest file on disk against the NPZ before training and abort on mismatch, and the demo bundle refuses to build when upstream metrics carry no manifest SHA. Datasets built before this manifest load only with explicit `legacy=True`, are flagged legacy, and cannot publish new benchmark evidence. The sanitized manifest (`data/split_manifest.json`, basenames only, no local paths) and dataset card (`data/dataset_card.md`) are now committed; the dataset NPZ stays gitignored.
### Docs
- Centered the README header: uniform dark badge labels and three action buttons in the dashboard palette (Open Demo, Explore Method, Run Locally).
### Fixed
- Sweep discriminator leakage (`examples/sweep.py`): the discriminator used to fit on generated validation windows and score on those same windows, and its docstring described train-regime generations the code never produced. The sweep now splits validation into temporally disjoint fit and score blocks separated by window length plus lookback (120s), generates each block separately from that block's regimes, fits the discriminator on the fit block only, and reports W1 and AUC on the score block. When either block is too small, the discriminator score is reported as insufficient instead of falling back to overlapping windows. `runs/sweep.json` now records the protocol version, the training data hash, the block sizes and gap, the selection rule, and the winner name, kind, and config.
- Demo config no longer silent (`examples/demo.py`): the DDPM config used to come from environment variables with hardcoded defaults, so it could drift from the sweep winner without any record. The demo now resolves its DDPM config from the frozen sweep winner when the winner is a neural model, requires all four explicit environment variables otherwise, and records the sweep winner (name, kind, source) in `runs/metrics.json`. A baseline sweep winner is recorded plainly.

## [v1.3.0] - 2026-10-18
### Added
- Book consistency audit (`flowforge/evaluate.py`). The generator emits log bid size, log ask size, and imbalance as independent features, but physically imbalance must equal (bid_sz - ask_sz) / (bid_sz + ask_sz). `book_consistency_table` measures the violation rate after inverse-transforming to physical units, plus negative implied spread/count checks. `constrain_imbalance` derives the imbalance feature from the generated sizes (constrained decoding). The full evaluation report now includes pre/post consistency tables and the marginal Wasserstein distance before/after the constraint.
### Tests
- 4 new regression tests in `tests/test_metrics.py` (violation detection; constraint fix yields zero violations).


## [v1.2.0] - 2026-10-18
### Fixed
- Elapsed-time honesty in market windows (`flowforge/data.py`). Seconds without quotes were dropped, gaps up to five seconds were tolerated inside a segment, and windows counted rows: a "60-second" window could span more than 60 seconds, and the first log return after a gap silently covered multiple seconds. The pipeline now follows a documented regular-grid policy: a new segment starts at every missing second, and the bar after a gap is dropped so the 1s log return is only ever defined where the previous second is present. Every accepted 60-row window now spans exactly 59 seconds between endpoints. Added regression tests: a missing-second fixture (cross-gap return dropped, segments split at the gap) and a chunk-boundary return test. Note: the window counts and evaluation metrics recorded in the README were produced under the old policy and should be refreshed on a full rerun.

## [v1.1.0] - 2026-10-16

### Fixed
- Autocorrelation evaluation (`flowforge/evaluate.py`). `flow_acf_table` concatenated signed order flow across overlapping windows (60s windows, 10s stride) before computing autocorrelation. That duplicated most of the data, scrambled temporal order at window junctions, and centered everything on the grand mean. On level-shifted synthetic data the old method reported lag-1 autocorrelation of 0.97 where the true value was 0.3. It now computes autocorrelation per window and averages across windows, with 95% confidence intervals. Added regression tests pinning the per-window behavior and CI coverage.

### Added
- Train-on-synthetic-test-on-real (TSTR) check (`flowforge/evaluate.py`). A logistic regression predicts near-term flow direction from generated windows and is tested on real test windows, next to the same model trained on real windows, with a majority-class baseline for scale. It is reported separately from the real-vs-generated discriminator, which asks whether synthetic windows are indistinguishable rather than whether they are useful. First run: diffusion-trained scores 0.626 (the majority baseline), VAE-trained scores 0.409, so the VAE's invented temporal structure is actively misleading.

### Changed
- Reran the VAE baseline and the DDPM (seed 7, same config) and updated the README with the new numbers: DDPM mean W1 0.280 (was 0.277), discriminator AUC 0.741 (was 0.669). The AUC moved between identical reruns because torch CPU training is not bit-reproducible across runs; I verified the discriminator itself is deterministic on fixed inputs, so the movement is training noise. The W1 moved only in the third decimal.

### Fixed
- Conditioning leakage in the regime features (`flowforge/data.py`). The volatility lookback was built as `mid[start - LOOKBACK:start + 1]`, which included `mid[start]`, the first second of the target window the model generates, contradicting the documented strictly-past conditioning. It now uses `mid[start - LOOKBACK:start]`. Added a regression test pinning temporal invariance: regime features for a window are identical when data at or after the window start is perturbed.

### Changed
- Reran the VAE baseline and the DDPM on the leak-free dataset (seed 7, same config as before) and updated the README with the new numbers. They came out effectively unchanged: DDPM mean W1 0.277 with discriminator AUC 0.669, VAE 0.527 with 0.956.
